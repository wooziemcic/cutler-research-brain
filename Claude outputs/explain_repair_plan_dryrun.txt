================================================================================================
THE CHUNK KEY DOES NOT NAME A TICKER
================================================================================================
  build_rag_index.py builds chunk ids as

      chunk_id = f"{document_id}_c{chunk_index:04d}"

  and rag_chunks declares `chunk_id TEXT PRIMARY KEY`, while chunks are written
  with INSERT OR REPLACE. The ticker is a COLUMN, not part of the key. So a
  document tagged with two tickers has ONE set of chunk rows, and building the
  second ticker REPLACES the first ticker's rows in place - same ids, same text,
  a new value in the `ticker` column.

  Nothing is deleted and the row count never drops, which is why this does not
  look like data loss. The chunks change owner, and the ticker that lost them
  reports them as missing on the next run. Repairing that ticker takes them
  back, and the next ticker's run takes them again.

  106 document(s) in this run are in exactly that state.

  This is NOT fixable by embedding. It is fixed by making the key name a ticker:

      py -3.11 scripts\migrate_rag_chunk_key.py --project-root "/home/claude/CutlerResearchBrain" --db "/tmp/claude-0/-home-claude/a9bffcda-c739-58a7-b47b-503dd7991d44/scratchpad/live/db.sqlite"

  which is a dry run by default and reports exactly what it would do.
